# Discipleship Assistant

A research, synthesis, diagnostic, design, measurement, and implementation assistant for building a church-wide culture of **disciples who make disciples who make disciples**.

## Architecture

This repository is the assistant's **operating system**. The Google Drive **Discipleship Brain** is the durable knowledge and evidence layer.

- **Drive = source library, Southbrook evidence, living synthesis, diagnostics, operating-system artifacts, measurement, experiments, and decisions.**
- **GitHub = constitution, routing, skills, agent definitions, integration rules, and tests.**

Do not duplicate the research corpus into GitHub.

## North Star

The goal is not attendance, program participation, knowledge, or volunteering alone. The goal is ordinary followers of Jesus who know and love Jesus, abide in Christ, become like Jesus, live on mission, share the gospel, help others follow Jesus, and equip others to do the same.

## Core workflow

`INTAKE → RETRIEVE → VERIFY → ANALYZE → SYNTHESIZE → DIAGNOSE → DESIGN → MEASURE → EXPERIMENT → DECIDE → LEARN`

For an explicitly requested one-command research run:

`CONTEXT → GAP → CONTRACT → DEEP RESEARCH → PRESERVE RAW → VERIFY → STRESS-TEST → COMPARE → UPDATE → PUBLISH PDF → FILE → SIMPLE-FIRST READOUT`

See `docs/full-research-cycle.md`.

Full-cycle research reports use the reusable house style in `docs/research-report-pdf-standard.md` and `templates/research-report-pdf-template.md`. The default final human-facing artifact is a professional PDF plus an editable DOCX master, with claim-level source keys beside supported claims.

For transferable learning, move from:

`PRACTICE → MECHANISM → PRINCIPLE → LOCAL APPLICATION`

For practical ministry design, use the fuller learning loop:

`LOCAL PROBLEM → PRACTICE LANDSCAPE → MECHANISM/EVIDENCE BACKBONE → SOUTH BROOK FIT → ACTION WARRANT → TEST/PILOT → IMPLEMENT SUPPORT → LOCAL LEARNING`

The system separates **research confidence** from **action warrant**. A low-risk reversible test can be responsible before an exact ministry practice is causally proven; broad scale/integration requires stronger local learning.

See `docs/research-practice-action-framework.md`.

## Learn a book or Brain section efficiently

Ask: “Teach me [book/file/folder link] efficiently. Give me practical learnings, tools for my tool belt, and insights for building [my project].” The manager uses `discipleship-practical-learning-distiller` to read the bounded material, teach its main ideas, create usable tools with worked examples, and show concrete applications. It runs start to finish without separate stage prompts.

Default output is a short chat/Markdown brief with source links and honest reading coverage. Add “save it in the Brain” to authorize saving a draft; learning does not require new empirical research or automatically change approved conclusions. See [the full workflow and examples](docs/practical-learning-workflow.md).

## Southbrook branding by default

Every authored document build uses `southbrook-brand-artifact-stylist`, including Google Docs and internal Brain records. It combines the verified church identity with observed Southbrook header/text patterns. All content routes inherit [the shared production workflow](docs/southbrook-document-build-workflow.md). Preserve originals, citations, and draft/approval labels. Backlog restyling is a separate requested batch.

## Evidence vocabulary

Keep these distinct: `DOCUMENTED_EVIDENCE`, `ORGANIZATIONAL_CLAIM`, `PRACTITIONER_OPINION`, `INTERPRETATION`, `HYPOTHESIS`.

Use confidence language: `HIGH CONFIDENCE`, `PROMISING`, `CONTEXT DEPENDENT`, `UNCERTAIN`, `CONTRADICTED`.

Use knowledge status: `CURRENT`, `PENDING`, `TENTATIVE`, `HISTORICAL`, `SUPERSEDED`.
