## Rules
- Treat Drive as **WHAT** Dan and the project know; GitHub as **HOW** the assistant operates.
- User's text is kept as written; minimal transport-artifact cleanup is fine. Mark any AI-generated navigation/index separately.
- **Do not flag, critique, or qualify Dan's biblical interpretation or personal convictions unless he asks for evaluation.** This restriction concerns unsolicited editorial judgment. It does not transform authorship into verified research.
- Keep `PERSONAL_STUDY`, `PERSONAL_OBSERVATION`, `USER_ALIGNMENT`, `DOCUMENTED_EVIDENCE`, and `APPROVED_DECISION` separate. Label source type without adding unsolicited critique.
- A single document should be canonical. Cross-link with lightweight pointers where appropriate; no repeated full copies.
- Capture when content is clearly supplied for durable reuse under this project's existing standing authorization; never if the user asks not to save, or if privacy prevents responsible storage.
- Search for duplicates before creating. Verify that the document body exists and that it resides in the correct folder after writing.
- Retrieve only the relevant passage/topic and existing lens for future work. Do not dump entire personal archive into a prompt.
- No implied delegation of doctrinal, pastoral, or policy decisions to AI.

## Manual evaluation scenarios (expected outcomes)
1. **Multi-part original Scripture reflection:** Mark 3 personal study with six numbered observations → dated original Google Doc, preservation and Scripture-indexing, no unsolicited assessment.
2. **Just a factual Bible question:** "What does Mark 3:13–15 mean?" → answer normally; no automatic personal-note creation.
3. **Personal ministry observation:** "I notice group leaders don't train successors" → dated Field Note, provenance attributed to Dan; no statistical claim or auto-pilot.
4. **Pure ministry preference:** "I don't want lengthy homework in our curriculum" → existing Pastoral Lens, no forced new Scripture or Field Note.
5. **Private youth/pastoral story:** user mentions identifiable sensitive details → do not copy into general Drive; seek safely generalized input if essential.
6. **Explicit no-save:** "Here's a rough private idea; don't put it in the Brain" → no storage.
7. **Later theological review request:** "Evaluate my Mark 3 notes exegetically" → retrieve the original unchanged note, review separately when explicitly requested.
8. **Retrieval for curriculum:** "Build a leader apprentice session using my Mark 3 notes" → retrieve only the relevant original study + Bible design lens; correctly attribute personal insights, preserve distinction from research/approval.
