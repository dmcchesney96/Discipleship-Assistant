# Learn from the Brain and build with it

Use `discipleship-practical-learning-distiller` to learn a book or bounded collection efficiently and carry its best ideas into your own work. You can simply point to the material and ask in ordinary language. The manager routes the request; you do not need to invoke each stage.

## Example requests

> Teach me this book efficiently: [Brain file link]. Give me the ideas worth keeping, tools for my tool belt, and examples I could use while building leader training.

> Run the practical learning workflow on [Brain folder link]. I have 10 minutes. Help me understand the material and show what it might change in my discipleship group resources. Save the brief in the Brain's Temporary Agent Outputs folder.

> Distill [exact resource title] in the discipleship Brain. I am building my own coaching process. Focus on useful questions, repeatable tools, and insights I would otherwise miss. No new empirical research and no saving this time.

> Resume the practical learning brief from [checkpoint/brief link]. Continue from the recorded unread section and keep the same source boundary.

If the assistant's environment does not load this repo's routing automatically, ask it to read `AGENTS.md` and `skills/discipleship-practical-learning-distiller/SKILL.md` in this repository first. GitHub stores these instructions; it does not run an AI job by itself. This workflow needs a session with access to the selected Brain sources. It adds no scheduled automation or GitHub Action that calls a model.

## What happens start to finish

1. Resolve your source pointer and what you are trying to learn/build. Missing building context defaults to general ministry use; an ambiguous source needs clarification.
2. Inventory the bounded material and read it. Record inaccessible or partially read items honestly. Large collections use batches and a resume ledger.
3. Explain the central argument and select the most useful lessons. Keep each source's meaning and attribution intact.
4. Teach those ideas with concrete examples and source pointers.
5. Create usable tools, with exact steps/questions and a worked example. Identify which came from the author and which are new adaptations.
6. Show specific ways the ideas could shape what you are building. Include a small next use and a short teach-back/application check.
7. Check source fidelity, coverage, usefulness, and reading length. Deliver one brief, with tools included.
8. If saving was authorized, verify the destination, avoid duplicate briefs, write, and read back the result. Otherwise deliver in the conversation. Report actual save status.

## What you receive

A 60-second orientation, a short connected teaching, usually 3–7 learnings and 1–3 usable tools, concrete building implications, a small next use, recall/application questions with an answer guide, and source/coverage notes. These are defaults, not quotas. Thin material yields fewer lessons; an important concept need not become a tool.

The default is a readable chat/Markdown brief, around 10 minutes to read. Ask for a shorter read, a deeper treatment, or a document format when useful. The [brief template](../templates/practical-learning-brief-template.md) defines the reusable output shape; the [skill](../skills/discipleship-practical-learning-distiller/SKILL.md) owns execution details.

## Choosing this workflow

| Your main goal | Workflow |
|---|---|
| Teach me this material and equip me to build with it | `discipleship-practical-learning-distiller` |
| Compare the evidence and strongest recurring findings across reports | `compare-big-picture` |
| Find out what is true through new research and verification | `full-discipleship-research-cycle` |
| Catalogue what practitioners actually do as Practice Cards | `discipleship-practice-intelligence-builder` / backfill |
| Decide what Southbrook should implement or pilot | `full-discipleship-practice-design-cycle` |
| Build the complete multi-session course and run-ready assets | `full-discipleship-curriculum-build-cycle` |

Ideas can be useful without empirical proof. This workflow attributes an author's teaching and marks proposed adaptations; it does not automatically establish effectiveness, change research confidence, or approve a ministry decision. A partial excerpt produces an excerpt-based brief, not a claim to have read the entire book. A folder of AI summaries stays a folder of AI summaries.

## Where the work lives

Actual sources and learning briefs belong in Drive. Workflow instructions and reusable templates belong in GitHub. Authorized durable learning packs now use `04 — RESEARCH INTELLIGENCE / 07 Practical Learning Library`, created at Dan's request during the first live run. Separate provider folders contain source-specific packs; a Start Here guide, master index, and tool-belt guide provide navigation. Temporary drafts can still use Agent Workspace, and a current user-named destination takes precedence. See [the library convention and live-test record](practical-learning-library.md).

For a large collection, distinguish coverage of every stored resource from complete reading of every published book. A focused first pass must be disclosed and labeled per resource. A full-book teaching requires the substantive book contents; a preview, extract, or index cannot stand in for them.

Saving does not automatically update Living Synthesis, the Master Principles Index, Practice Intelligence, your convictions, or Southbrook decisions. Reusable learning can be deliberately promoted later through the relevant workflow. This keeps a helpful book idea easy to retrieve without turning it into an approved conclusion.
