# Evidence → Durable Principle System

## Purpose

Make the Google Drive Discipleship Brain more **selectively intelligent**, not simply bigger. It must produce a small, traceable, revisable set of insights that help ordinary Christians abide, mature, live on mission, intentionally disciple others, and foster further generations. GitHub stores process; Drive is canonical evidence and synthesis.

## Brain boundaries

- **02 External Evidence**: original material, research papers, AI-generated inputs clearly labeled.
- **04 Research Intelligence**: claims/audits/contradictions, a **Master Principles Index** inside 04 Strongest Converging Principles, open verification queues, concrete Practice Intelligence separately.
- **05 Living Discipleship Synthesis**: 15 topic-owning documents/folders with full principle records and version history.
- **06 Southbrook Diagnostic**: local observed reality, not universal evidence by itself.
- **09 Experiments/Pilots/Learning**: local results and implementation fidelity.
- **10 Strategy & Decisions**: recommendations vs actual approved policy.

Do not create a competing root or replace source originals. Find live canonical folder IDs before writing. Master Index is a thin cross-domain navigation layer, NOT a second copy of all conclusions.

## Core pipeline

1. Context-retriever: look up current synthesis/claims/index and find whether the topic is already answered.
2. Source-evidence-checker / AI verification: evaluate source existence and exact support, preserving provenance.
3. Compare-big-picture: surface key learnings and *Candidate Principle Dispositions*.
4. Pattern-connector: de-duplicate independent source families and test mechanism plus rival explanations.
5. Living-synthesis-maintainer: decide epistemic change, write traceable principle record if warranted.
6. Librarian: verify live Drive source links, topic record and Master Index; report sync status.

For the **existing backlog** use discipleship-principle-backfill as an explicitly requested bounded orchestrator, with a resumable manifest. For concrete how-to practices use discipleship-practice-intelligence-backfill instead; these knowledge products are related, not interchangeable.

## Distinctions the system must preserve

- Original evidence vs derivative narrative / unverified AI report.
- Documented practice vs reported organizational outcome vs independent outcome evidence vs adjacent-domain mechanism.
- Repeating a claim three times vs three independent primary source families.
- A plausible explanation vs a demonstrated causal mechanism.
- Spiritual formation vs participation; disciple-making vs volunteering; generations of people vs groups vs churches.
- Project-confidence level vs the prudence of a low-risk, reversible Southbrook experiment.
- Hypothesis, proposed strategy, pilot, and actual approved decision.

## Evidence to principle promotion gate

Promotion requires a specifically bounded claim, linkable assessed sources, mechanism and limitations, a source-family independence check, meaningful counterevidence search, a confidence rationale, and a documented material knowledge impact. High confidence is not a reward for citation count. Some claims can remain PROMISING/CONTEXT DEPENDENT when mechanism research is stronger than church-level outcomes.

Use templates/durable-principle-record-template.md. Preserve stable IDs, previous confidence/wording and version rationale; never overwrite a superseded view without history. No arbitrary number of principles is required. If source access or confidence is inadequate, file a lead in Research Intelligence; do not promote it.

## Master Index contract

Use templates/principle-master-index-template.md. One row per unique principle ID; topic document is owner, index is a pointer. On authorized changes, update and verify both. If either write fails, report INDEX OUT OF SYNC explicitly; do not claim complete synchronization. Search title/meaning before adding an ID.

## Batch/recovery contract

Use templates/principle-backfill-manifest-template.md. Inventory first, assess valuable source families in bounded batches, update checkpoint after each; explicitly distinguish INVENTORIED vs DEEP REVIEWED. Resume from the last checkpoint and avoid recreating principle records on retries. Stop once incremental review stops materially changing warranted principles, with remaining high-value gaps in a targeted queue.

## Acceptance checks

1. Same underlying study repeated in multiple AI reports counts as one source family.
2. Strong adjacent-domain learning evidence does NOT become proof of multiple-generation disciple-making.
3. Two credible contradictory studies remain visible; claims narrow/complicate rather than erase contrary data.
4. Case-study popularity alone yields Practice Intelligence, not high-confidence causal conclusion.
5. Already-known candidate receives NO DURABLE CHANGE or an update to an existing ID; no cloned principle.
6. A claim with unverifiable source is flagged or deferred; it is not promoted.
7. One-line plain-language principle is intelligible to a ministry volunteer.
8. Exact source links, as-of status, history, index sync and manifest checkpoint remain recoverable.

See tests/principle-synthesis-cases.md for executable review examples. For a code-free repository these are behavioral acceptance tests, not claims of automated statistical validation.
