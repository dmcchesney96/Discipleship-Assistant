# Change Management

Meaningful changes to the Discipleship Assistant operating system should be traceable and reversible.

## Rules

1. Preserve a working version before material experimentation.
2. Use a branch/PR for substantial changes when practical.
3. Describe what changed, why, and which evidence/learning motivated it.
4. Never silently weaken evidence standards, privacy, approval boundaries, or the North Star.
5. Skill changes should preserve narrow responsibility; avoid turning every skill into a general-purpose agent.
6. When a Drive workflow changes, update `docs/drive-map.md` / routing docs as needed.
7. When a decision changes, preserve the previous decision and rationale as historical/superseded rather than rewriting history.

## Review triggers

Review architecture when:

- folder structure materially changes;
- a skill repeatedly overlaps another;
- new evidence standards are adopted;
- a new recurring research/diagnostic workflow emerges;
- current working language becomes formally approved or is replaced;
- measurements begin driving real coaching/pastoral decisions.
