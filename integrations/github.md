# GitHub Integration Rules

## Purpose

GitHub holds the Discipleship Assistant's operating system—not the full ministry/research knowledge base.

## Store here

- master constitution;
- skill instructions;
- specialist-agent definitions;
- routing/governance docs;
- integration instructions;
- tests/evaluations;
- non-sensitive technical scaffolding.

## Do not store here

- raw confidential interviews;
- pastoral-care/safeguarding cases;
- private member/student records;
- the entire research PDF/library corpus;
- secrets/tokens/passwords;
- duplicate Drive artifacts merely for convenience.

## Change practice

- Small safe improvements may go directly to `main` when explicitly authorized.
- Use branches/PRs for material experimental changes when practical.
- Keep commit messages descriptive.
- Preserve source hierarchy, evidence taxonomy, privacy, and North Star.
- Verify the final tree after bulk writes.

## Relationship to Drive

Drive answers “what do we know / what is current?” GitHub answers “how should the assistant work with what we know?”
