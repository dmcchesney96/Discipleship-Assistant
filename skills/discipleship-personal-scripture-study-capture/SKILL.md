# Personal Scripture Study Capture

## Mission
Preserve Dan's developing understanding of Scripture and its discipleship applications in his own words so the Brain can retrieve those studies in future Bible, training, leadership, and curriculum work. This is **capture**, not an automated exegetical-review or church-doctrine-approval pipeline.

## Routing and scope
Use when Dan contributes substantive, original reflection on a named biblical passage, explicitly asks to save personal Bible notes, or clearly presents material for this personal study library.

Do **not** trigger merely because Dan asks for facts about a passage, requests research on a biblical question, supplies a sermon to format, or quotes a source without offering his own notes. For general preferences about how Bible curriculum should be designed, use `discipleship-convictions-capture`. For eyewitness ministry observations unrelated to a passage, use `discipleship-ministry-field-notes-capture`.

When the same input is also a durable discipleship conviction, store the complete original study **once** here; add only a short, attributed link to the existing Pastoral Lens if this would genuinely improve future design. Do not duplicate the entire study in multiple folders.

## User authority and non-editorial boundary
Dan explicitly requested this capture system and the initial study on October 21, 2026. Treat this as authorization to capture clearly supplied, nonsensitive personal Scripture-study content for the Brain, unless Dan says not to save it.

**Do not flag, critique, correct, rank, discredit, or qualify Dan's biblical interpretations or theological conclusions unless he explicitly requests such analysis.** Do not perform background validation or insert unsolicited caveats in the study. The user's original voice is the priority.

Keep separate authorship and source status in indexing: `PERSONAL SCRIPTURE STUDY / USER-AUTHORED REFLECTION`. This is a classification of authorship, not a negative judgment or assessment of truth. Never quietly recast it as peer-reviewed scholarship, external evidence, formal church teaching, or an approved Southbrook decision.

## Capture procedure
1. Check that the note is not already captured; prefer updating the existing note if Dan asks for a revision.
2. Record date of capture (do not invent date of original composition), Scripture reference(s), and Dan's title/topic. Suggested file naming: `YYYY-MM-DD — Book chapter:verses — User Title`.
3. Preserve the complete supplied wording, structure, and substance. Clean transfer artifacts such as `&#x20;` and apply readable formatting without changing meaning, claims, or grammar unless Dan requests editing.
4. If useful, add minimal *clearly separate* administrative metadata such as date, Scripture references, origin, and topical indexing. No added exegetical analysis without permission.
5. Create native Google Doc, put it in the verified canonical folder, and read it back to verify content and parent folder. Never treat a create success without body content as complete.
6. Link the note in the folder guide/index only if that meaningfully helps navigation. Avoid growing a duplicative index when Drive search is sufficient.
7. Optionally link one or two genuinely durable convictions to the Pastoral Lens by pointing back to this primary document, without claiming evidence or Southbrook adoption.

## Retrieval procedure
When Dan asks for work involving a passage or a connected concept, retrieve this folder using exact passage/book and relevant theme. Fetch only matching notes. Quote or paraphrase with attribution `Dan's personal notes`; do not silently mix his statements with Scripture text, scholarship, organizational evidence, or existing church decisions.

If asked to research or verify a claim in a note, run the appropriate research/theological workflow **then**, clearly separating findings from the original unchanged document.

## Privacy and exclusions
Do not copy identifiable counseling material, sensitive family stories, personally identifying youth information, or safeguarding disclosures into the general Brain. Ask for a safely generalized version when necessary.

## Completion
Report the document link, passage, verified folder location, and whether cross-links were made. Never imply a note was evaluated when it was merely captured.

## Acceptance tests
- Dan supplies a multi-section Mark 3 study with personal applications: file exact words under Scripture folder; no unsolicited critique.
- Dan says "Explain Mark 3": provide an answer; do not create a personal note.
- Dan says "I changed my understanding of Mark 3; update the study": update/version the existing study with traceable revision; avoid duplicate.
- Dan says "Don't save this": do not persist.
- Dan supplies a pastoral counseling example with identifying details: avoid general Brain capture until safely generalized.
