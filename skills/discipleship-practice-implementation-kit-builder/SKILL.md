# Discipleship Practice Implementation Kit Builder

## Purpose

Bridge the gap between **a good pilot design** and **something ordinary leaders can actually carry**.

The goal is not to create a giant curriculum. The goal is the smallest complete set of tools needed to preserve the mechanism, reduce friction, support leaders, and learn faithfully.

## Trigger

Use when:

- a practice/test/pilot has already been selected or clearly proposed;
- the user asks to make it ready to run;
- leaders need training/materials/coaching tools;
- a pilot charter exists but implementation assets do not.

Do not use this skill to decide which practice Southbrook should choose. Use `southbrook-practice-fit-assessor` / `discipleship-experiment-pilot-designer` first.

## Inputs

- Practice Card / selected practice;
- Pilot Charter;
- target people;
- hypothesis/mechanism;
- duration/cadence;
- theological/pastoral guardrails;
- maturity/authority boundaries;
- coaching/support plan;
- measurement plan;
- Southbrook language/branding requirements when relevant.

## Design principles

1. Preserve the mechanism, not every external program detail.
2. Separate **FIDELITY ESSENTIALS** from **ADAPTABLE ELEMENTS**.
3. Reduce staff dependence.
4. Design for an ordinary volunteer/believer to understand and carry.
5. Keep participant tools simple enough to reuse and teach.
6. Build coaching/correction into the system rather than relying on perfect initial training.
7. Avoid unnecessary content volume.
8. Make next-generation reproduction explicit when the pilot is about disciple-making.
9. Include safeguards for doctrine, pastoral care, confidentiality, minors, or authority when relevant.
10. Integrate measurement naturally; do not turn the ministry experience into paperwork.

## Required kit

Create only the pieces actually needed, usually:

### 1. One-page practice overview
- purpose;
- who it is for;
- what happens;
- cadence;
- key expectations;
- North Star connection.

### 2. Leader quick-start guide
- before launch;
- session/rhythm flow;
- what to do if stuck;
- escalation/pastoral boundaries;
- fidelity essentials;
- adaptable elements.

### 3. Participant tool
The simplest reproducible guide/card/questions/process people actually use.

### 4. Training outline
Usually 45–120 minutes depending on complexity:
- why;
- model/demo;
- practice/rehearsal;
- feedback;
- common mistakes;
- first action.

### 5. Coaching rhythm
- check-in cadence;
- questions;
- observation/feedback;
- troubleshooting;
- adaptation decisions.

### 6. Launch checklist
- people confirmed;
- training complete;
- tools ready;
- permissions/safeguards handled;
- baseline/measurement ready;
- first meeting/action scheduled;
- review date scheduled.

### 7. Measurement prompts
Only the small set needed for implementation + discipleship learning.

### 8. Troubleshooting guide
Common friction:
- nobody starts;
- sessions become teaching-heavy;
- leader dominates;
- practice becomes paperwork;
- people miss meetings;
- theological confusion;
- no reproduction;
- staff begins carrying what participants should own.

## Reproducibility test

Before finishing, ask:

- Can an ordinary believer explain this in two minutes?
- Can they begin with limited staff help?
- Can they practice it, not only understand it?
- Can they teach another person to do it?
- Can coaches correct drift without taking ownership back?
- Does the tool preserve relational/theological depth while staying simple?

If not, simplify.

## Output

# Minimum Viable Implementation Kit — [Pilot/Practice]

- Practice overview
- Leader quick-start
- Participant tool
- Training plan
- Coaching plan
- Fidelity essentials vs adaptable elements
- Launch checklist
- Measurement prompts
- Troubleshooting
- Safeguards
- Files/artifacts created
- What still requires human approval

## Persistence

Proposed/temporary implementation assets belong in Agent Workspace or the relevant pilot folder until the pilot is approved.

Approved active-pilot assets belong with the pilot in:

`09 — EXPERIMENTS, PILOTS & LEARNING → Active Experiments & Pilots`

Do not imply that a toolkit is an approved ministry rollout merely because it has been created.
