# Ministry Practice Source Verifier

Check whether a methods account faithfully describes its original and whether enough detail is documented to understand it. Do not select a local practice, certify theology, infer effectiveness or launch unrelated research.

Accept bounded claims/operational fields, draft cards/report, source ledger, dates/versions and intended use. Use `references/operational-verification-register.md`. Preserve existing IDs.

## Procedure
1. Open the actual original at relevant pages/sections/timestamps/rows. Record FULL RELEVANT INSTRUCTIONS / PARTIAL EXCERPT / SUMMARY ONLY / INACCESSIBLE. Snippets and generated reports are not inspected originals.
2. Split compound claims: frequency, group size, readiness, coaching and outcomes need separate support. Check every implementation-critical claim in serious cards; report checked/unchecked coverage and priorities. Use atomic claim or field IDs; a compact grouped display is acceptable only when every included field has its own source locator and disposition. Never count bundles as if they were individual checked claims.
3. Classify what the source establishes:
   - PRESCRIBED METHOD: published instructions/intended process.
   - REPORTED USE: firsthand account of use, scoped by time/place.
   - OBSERVED USE: actual observation/record of enactment with provenance; never inferred from a manual.
   - REPORTED OUTCOME: attributed organizational/practitioner result.
   - EFFECT / MECHANISM / THEOLOGICAL CLAIM: separate assessment when consequential.
   These describe claims, not a universal confidence scale. Preserve existing Core strength and audit statuses separately. For legacy OBSERVED PRACTICE cards based on manuals, clarify that documentation establishes the prescribed method, not observed compliance.
4. Compare meaning, actors, sequence, quantities, time, exceptions and context. Retain faithful paraphrases and exact locators; quote sparingly. Trace derivatives to source families; repeated reports of one manual are not independent implementations.
5. Use existing audit statuses VERIFIED / SUPPORTED / PLAUSIBLE / UNVERIFIED / MISLEADING / CONTRADICTED. VERIFIED applies only to the bounded factual claim directly checked; it never establishes a causal outcome. Preserve source-evidence-checker Strong / Moderate / Limited and rationale when assessed; do not infer one scale from another.
6. Check edition/date and historical/current use. Preserve conflicting versions with scope; never silently merge them. If the latest source is unreadable, mark currency unverified. Omitted coaching is unknown, not absent in reality.
7. Assess operational completeness separately for actors, sequence, cadence, tools, preparation, attempted practice, feedback, readiness/authority, oversight, struggle support, burden, handoffs and relevant reproduction. Use DOCUMENTED / PARTIAL / UNKNOWN / NOT APPLICABLE per field. Explain what gaps prevent: description, comparison or local implementation. Completeness is not quality/effectiveness.
8. Recover documented failure cases and contextual limits; otherwise label inferred risks and unavailable negative-case evidence. Inspect tool availability/version/rights when reuse matters. Public access does not grant adaptation rights.
9. Route consequential causal/outcome/theological/generational claims to `source-evidence-checker`; use `ai-research-verification-integration` for report-level AI claims. Scale checks to the claim: absent causal studies do not invalidate documented instructions; accurate instructions do not validate outcomes.
10. Return corrected wording and retain/qualify/remove/follow-up disposition. Preserve the raw report; do not promote proposals to approved practice.

## Output
Return claim ID, bounded claim, type, source/version/locator, access depth, status, support, contrary/missing detail, corrected wording, completeness consequence and next action. Include originals reopened; checked/unchecked counts; gaps affecting description/comparison/implementation; separate outcome assessment; source-family/version conflicts; exact report/card corrections; actual save status; and whether verification was fresh-agent or a same-agent source-based second pass.

Stop after the requested claims and essential follow-ups. If originals are inaccessible, preserve UNVERIFIED with the needed check and return a limited result. Never invent operational details to make a card complete.
