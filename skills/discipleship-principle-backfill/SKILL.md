# Discipleship Principle Backfill

## Mission and authority

Turn an existing corpus into a **small, trustworthy, revisable set of portable mechanisms/principles**—not summaries, practice lists, or automatically approved Southbrook policy. Use the canonical Google Drive Brain for evidence and syntheses and GitHub for process only. Follow AGENTS.md, docs/principle-synthesis-system.md, docs/skill-routing.md, the appropriate source/evidence skills, and existing Drive folder architecture.

Use when asked to audit/backfill a collection (e.g. whole Brain, AI reports, Exponential books, selected domain). Do not invoke solely for a single new report, a specific practice mining request (use discipleship-practice-intelligence-backfill), or to write a general short summary (use compare-big-picture).

A full backfill is an **authorized multi-stage workflow only when requested**. It may update internal Brain records within the user's requested scope, subject to evidence and access gates. No approval of Southbrook policy or external communication follows.

## Workflow

1. **Scope/manifest.** Resolve canonical root and actual folder IDs in Drive. Inventory the full requested source boundary at metadata level: stable file IDs, titles, type, original/derived, topical domain, publication and assessment status, processing state, version, source-family lineage, links. Create/update the manifest using templates/principle-backfill-manifest-template.md. Inventory is NOT a claim that the content was deeply reviewed.
2. **Deduplicate/triage.** Group exact copies, formats, AI summaries and dependent works by original family. Prioritize assessed original research, primary practice descriptions, contradictions, high-value gaps, and sources most likely to alter existing knowledge. Label reference-only/low-yield sources rather than deeply processing all of them.
3. **Retrieve baseline.** Get current topic Living Synthesis, Strongest Converging Principles, Master Principles Index and related claims/audits, using the smallest sufficient context. Treat missing/empty folders as missing knowledge, not evidence no knowledge exists.
4. **Extract candidates.** State claim, actual outcome, context, unit (disciples/leaders/groups/churches), proposed mechanism, original locator, independent family, counterclaim, what is new vs already known. Mark descriptive church practices for Practice Intelligence; do not count their popularity as causal evidence.
5. **Verify consequential claims.** Route raw AI-derived or uncertain claims through ai-research-verification-integration and source-evidence-checker; reopen strongest accessible original sources. Check source existence, method, directness, denominator, data independence, adjacent-domain inference, theological boundaries and disconfirming evidence. Unresolved cases go to Verification Queue or Research Gaps, NOT automatic principle promotion.
6. **Compare and connect.** Use compare-big-picture on bounded batches and pattern-connector for genuine cross-source mechanisms. Distinguish source family from report count; state alternative explanations and failure modes.
7. **Decide impact.** For each candidate record NEW DURABLE PRINCIPLE / STRENGTHENS / NARROWS / COMPLICATES / CONTRADICTS / NEW LEAD / REPEATED PRACTICE ONLY / NO DURABLE CHANGE. Document reasoning. Do not create a principle when existing record should be updated.
8. **Persist warranted knowledge.** Route only verified/assessed material through living-discipleship-synthesis-maintainer. Use templates/durable-principle-record-template.md, allocate stable IDs through the live Master Principles Index, preserve old versions and source links, and verify topic document + index match. Add unresolved leads to Research Intelligence and operational methods to Practice Intelligence via their own skills when warranted.
9. **Batch checkpoint.** After each bounded domain/source batch update manifest with processed, reviewed, deferred, skipped, links, decision, reason, blocked items, and next resume pointer. Never claim all sources were read if only inventoried. New evidence need not create new principles.
10. **Completion gate.** Stop when all requested sources are inventoried, important source families assessed or explicitly deferred, the best candidate principles have documented decisions, current index/syntheses are synchronized, and remaining work is genuinely a targeted verification or missing-source queue. Do not force a numerical quota. Otherwise record IN PROGRESS or BLOCKED, precise remaining scope, and next batch.

## Output contract

- Corpus and as-of date, accurate coverage counts: inventoried / deep-reviewed / already-assessed / deferred / reference-only.
- Source-family and duplicate map.
- Candidate principle dispositions and exact source links.
- New/changed/retained principle IDs + evidence reasoning, confidence transitions and contrary evidence.
- Index and topic synthesis write verification (or explicitly BLOCKED).
- Practice-only leads and research gaps handled separately.
- Checkpoint manifest link, next resume pointer, honest completion status.
- Plain-language 3–7 significant learnings; avoid summary inflation.

## Stop / safety rules

Do not duplicate the entire raw corpus in GitHub. Never write identifiable student, pastoral-care, medical, safeguarding, or private interview material to a general principle record. Do not silently publish a proposed Southbrook strategy as proven or current. If originals cannot be accessed, preserve uncertainty and stop that claim's promotion. Do not mutate Drive structure, delete, change sharing, or introduce duplicate syntheses to appear productive. Follow repo stop rules.

### Manifest status vocabulary

Use INVENTORIED for metadata-only review, ASSESSED ALREADY for a credible prior audit, DEEP REVIEWED only after a meaningful source-level assessment in this run, DEFERRED for an intentional queue, REFERENCE ONLY for low-yield material, and BLOCKED for inaccessible or unsafe sources. Never make deep-review counts equal inventory counts without source-level work.
