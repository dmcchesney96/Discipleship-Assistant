# Full Practical Ministry Research Cycle

## Outcome and boundaries
Help a leader understand credible methods, explain their differences, recover how they work, and preserve useful learning. Connect the question to ordinary people following Jesus and helping others follow him. Do not require every study to demonstrate multiplication.

Own the complete sequence:
`QUESTION → EXISTING KNOWLEDGE → PRACTICAL CONTRACT → PRIMARY METHODS → RAW REPORT → SOURCE VERIFICATION → OPERATIONAL COMPARISON → PRACTICE INTELLIGENCE → WARRANTED LEARNING → FINAL REPORT → VERIFIED FILING → STOP`.

Distinguish adjacent work:
- Use `full-discipleship-research-cycle` for primarily truth/effectiveness questions.
- Use this cycle for new external investigation of church methods. Start without a local diagnostic when the question is descriptive.
- Use `full-discipleship-practice-design-cycle` for choosing what Southbrook should implement or test; do not run that whole cycle merely to finish practical research.
- Use `full-discipleship-resource-equipping-cycle` for evaluating actual worksheets/exercises/guides. Call a narrow specialist only when requested or necessary to understand a method.
- Use curriculum architecture for a complete course; source distillation for teaching a supplied book without new investigation.

Honor review-only, no-save, source-only and format overrides. A full-cycle request authorizes bounded internal artifacts and Brain writes within verified existing destinations. It does not authorize sending, spending, ministry launch, staffing commitments, sharing changes, deletion, doctrinal approval, or governance changes. Never invent interviews, site visits, local capacity, participant outcomes or adoption.

## 1. Question and existing knowledge
Use `ministry-context-retriever` for relevant Practice Cards, comparisons, source families, gaps and synthesis. Respect named collections. For agenda-selected work, use the scout only with adequate current context; otherwise state novelty/priority is unverified. When existing assessed material answers the question, stop new external research and complete the requested comparison/readout and warranted filing without manufacturing novelty.

State the practical question, audience, useful capability/decision, scope, exclusions, comparison unit, source boundary and stopping condition. Distinguish people, leaders, groups and churches. Retrieve the pastoral alignment lens when local design/fit materially affects judgment. Missing local context does not block a descriptive study.

## 2. Practical research contract
Use `daily-discipleship-research-prompt` (installed alias `prompt`) in SELF_EXECUTE mode with intent PRACTICE INTELLIGENCE; use HYBRID only when substantive effect investigation is requested. Preserve its exact executor handoff. Use `references/practical-research-contract.md` for practical fields and report order.

Specify meaningfully distinct implementations based on the question and available material; do not pad a 5–15 quota. Require primary manuals, actual training instructions, practitioner books/interviews, church/network artifacts or substantive historical accounts. Promotional pages are leads until operational detail is inspected. Include ordinary/smaller contexts and a relevant alternative where available; disclose selection bias and access gaps.

Academic research is a targeted corrective for consequential mechanism/effect claims, not a mandatory parallel literature review. Direct causal proof of a named program is not required to preserve a useful method. Practitioner agreement does not establish an outcome.

## 3. Investigate and preserve raw output
Use `discipleship-deep-research-executor` in PRACTICE INTELLIGENCE mode with the practical contract/artifact order. Recover who initiates/participates, steps, cadence, tools, preparation, demonstration, attempted practice, feedback, readiness/authority, handoffs, oversight, help when struggling, burden and ownership/reproduction where relevant.

For each field retain source ID, exact page/heading/timestamp, date/version, access depth and support. Mark UNKNOWN when absent. Missing source detail is not proof the ministry lacks support. Distinguish prescribed instructions, reported use and observed enactment. Never reconstruct an inaccessible manual from snippets or an AI report.

Preserve the complete raw report, operational register and source ledger separately before correction in authorized existing Brain locations. Record the raw artifact or emitted raw stage before reopening originals; do not reconstruct a supposed raw draft after corrections. With external saves excluded, retain a local intermediate when allowed; with all file writes excluded, emit the raw stage in the conversation before continuing. If saving is blocked, continue useful work with an honest local-only checkpoint and exact failure. Never call scratch durable.

## 4. Verify against originals
Use `discipleship-practice-source-verifier`; reopen originals rather than rereading generated prose. Prefer a fresh verifier where available. If the same agent performs the second pass, disclose that limit; do not call it independent review.

Check every implementation-critical claim in serious candidate cards: steps, cadence, authority, coaching and tool availability. Separately triage consequential outcome, causal, theological and generational claims to `source-evidence-checker` / `ai-research-verification-integration`. Check source access, date/version, historical/current method, source-family dependence, contradictions, burdens and rights when reuse matters. Correct the final account and preserve the raw one.

Keep operational confidence and effectiveness confidence separate. A fully described method may lack reliable effect evidence; an impressive outcome report may lack enough implementation detail to replicate it.

## 5. Compare and capture practices
Use `discipleship-practice-intelligence-builder` in CAPTURE MODE. Reuse stable existing cards and source families before creating records. Deepen a case only for a consequential unclear system dependency. Compare actual tasks and support rather than reputation or slogans.

Include distinct methods/variations, core versus adaptable features, similarities from shared sources versus independent contexts, burdens/failure modes, conditions and unknowns. Attribute inferred mechanisms. Do not flatten incompatible theological/relational assumptions into a universal recipe. Explain useful learning; reserve Southbrook action-warrant verdicts for local-fit assessment.

## 6. Route learning
- Methods/cards/comparisons → existing Practice Intelligence Library under Research Intelligence.
- Actual resource reviews → verified Resource & Equipping destination when requested; never invent or number a folder.
- General principles → `living-discipleship-synthesis-maintainer` only when assessed evidence materially changes a supported conclusion. NO DURABLE CHANGE is valid.
- Local test proposals/results → existing experiment area only when in scope.
- Current local practice/approved decisions → authoritative records only with actual evidence and authorization.

Do not force practical findings into Living Synthesis. A reusable practice comparison can be the main learning product. Completion does not require a pilot, new principle, branded tool or ministry adoption.

## 7. Publish, verify filing and finish
Use `discipleship-research-report-publisher` with PRACTICAL report order from the bundled contract: lead with methods, operational examples and comparison; place technical audit afterward. Default a requested full report to professional PDF plus editable master; respect format overrides. Follow artifact skills and visual QA. If publication is blocked, preserve structured final content and mark the requested output blocked.

Use the librarian to verify authorized artifacts, parent destinations, deduplication, links and index updates. Report each write VERIFIED / PROPOSED / BLOCKED / EXCLUDED rather than inferring success.

Return useful learning first: 3–6 plain sentences, concrete examples, important differences, documentation confidence, reported results/limits, practices captured, actual saved links, changed/retained conclusions, coverage gaps and one next move only if needed. Do not claim a best model or local fit from descriptive research.

## Checkpoints, fallback and completion
After each major stage retain one checkpoint: run ID, date/timezone, scope, stage statuses, source access depth, exact artifact IDs/links, confirmed writes, pending/failed outputs and next exact action. Include a restart instruction usable without chat/scratch; deduplicate on resume. Never schedule continuation without a requested time/condition.

Load companion skills by exact name from the repo/installed checkout. If unavailable, perform the bounded transformation from this contract and disclose the fallback; never claim a missing skill ran. Stop recursive handoffs that add no evidence or required transformation.

Use COMPLETED only when requested investigation, verification, comparison, outputs and authorized filing are verified or explicitly excluded by the user. Otherwise use IN PROGRESS or BLOCKED and preserve completed work. Source limitations can support a completed bounded report when disclosed; a failed requested save/publication cannot be silently treated as completion.
