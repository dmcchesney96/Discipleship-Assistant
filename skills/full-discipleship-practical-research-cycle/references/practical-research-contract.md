# Practical contract and report order

Record question, as-of date/timezone, audience/capability, scope/exclusions, existing knowledge/source families, unresolved practical gap, primary-source requirements, distinct implementations, operational fields, contrary cases, search bounds/stopping rule, source access/version limits, requested outputs, filing destinations/status and completion criteria.

## Raw/final report
1. Useful learning in ordinary language.
2. Scope, starting knowledge, sources/access and actual investigation.
3. Practice landscape: distinguish methods, brands, tools and settings.
4. Implementation accounts: roles, steps, cadence, materials, training, practice, feedback, readiness, oversight, burden, struggle support; mark unknowns.
5. Worked example labeled source-described or original illustration; never present a constructed example as observed.
6. Comparison: differences, repeated patterns, prerequisites, tradeoffs and alternatives.
7. Documented instructions versus use/results, independent effect evidence, inferred mechanism, theology and proposed application.
8. Failure modes, negative cases, transfer conditions and questions.
9. Useful practices to preserve and existing-card reuse; local design handoff only if requested.
10. Verification corrections, operational register, complete linked source ledger and coverage limits.
11. Brain impact, unchanged conclusions and actual save/publication/index status.

## Per-method record
Stable method/card ID; provider/setting; version/date; problem; prescribed/reported/observed use; actors; sequence; group size; cadence; tools; training; modeling; attempted practice; feedback; readiness; authority/oversight; struggle support; handoffs; burden; ownership/reproduction; outcomes by source; inferred mechanism; failure/context limits; source/locator/access per critical field; unknowns.

Inspect fewer cases deeply when useful rather than padding shallow descriptions. Missing fields are not zero/absent practice. Preserve source → method → card → comparison traceability. No local implementation verdict without local evidence.

## Resume checkpoint
Run ID; timestamp/timezone; boundary; stage status; original versions/access; raw/corrected outputs separately; exact durable links versus local-only paths; reused IDs; confirmed writes/partial failures; publication QA; index sync; next action; self-contained restart instruction. Read confirmed artifacts before continuing; do not replay writes.
