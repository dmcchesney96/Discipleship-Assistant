# Pattern Connector

## Purpose

Make the Brain smarter as evidence accumulates instead of becoming a warehouse.

## Workflow

1. Define the pattern/question narrowly.
2. Gather already-assessed evidence from independent sources and/or local evidence.
3. Compare definitions, populations, units, mechanisms, and outcomes.
4. Identify:
   - convergence;
   - meaningful disagreement;
   - context-specific practices;
   - recurring failure modes;
   - plausible mechanisms;
   - research gaps.
5. Distinguish external convergence from Southbrook-local confirmation.
6. Distinguish a **repeated practice pattern** from a **transferable principle**. Repeated use across churches can justify a Practice Intelligence pattern without proving the practice causes the outcome.
7. Formulate a transferable principle only when evidence supports it.
8. Tag confidence and state what would falsify/change the conclusion.

## Output

- Pattern statement
- Evidence map
- Convergence/divergence
- Mechanism candidates
- Principle (if warranted)
- Southbrook relevance
- Confidence
- Open questions / next research

Do not update the Living Synthesis automatically; route a supported mechanism/principle change to `living-discipleship-synthesis-maintainer`.

When the main new learning is **how a practice is implemented or repeated across contexts**, route it to `discipleship-practice-intelligence-builder` / Practice Intelligence Library instead.

## Pattern evaluation protocol

Before calling a finding `convergence`, build a source-family map:
- **Observed claim:** one falsifiable statement, outcome, unit, and population.
- **Underlying origin:** original study/dataset, primary church practice material, interview collection, or self-report (with locators).
- **Family ID:** group source derivatives that reuse the same origin, including alternative formats and AI reports.
- **Independent families:** count only independently obtained primary evidence; related ministries or reports using the same dataset do not count separately.
- **Evidence role:** documented practice, reported outcome, mechanism support, direct outcome, local observation, interpretation or hypothesis.
- **Limits:** selection effects, absent denominator, conflation of generations, context differences, publication bias and possible alternative explanations.

Stress-test the mechanism: what else could explain the observed pattern? What evidence disagrees, what failed cases exist, and is the outcome actually formation/disciple-making/multiplication rather than engagement? Separate *church practice convergence* from *outcome corroboration*.

Use a cross-source evidence matrix when more than two families are involved. It should display source family, population/context, practice, mechanism, measured or reported outcome, source independence, support and contradiction. Cross-domain empirical mechanism support must be labeled as **adjacent-domain**, not direct proof of a discipleship result.

Disposition for each candidate: REPEATED PRACTICE ONLY / MECHANISM SUPPORTED / PRINCIPLE CANDIDATE / CONFLICT / NEW LEAD / NO DURABLE CHANGE. Forward only a warranted principle candidate or material correction to `living-discipleship-synthesis-maintainer`. Never update the synthesis independently.

Required output additionally includes distinct source-family count, explicit counterevidence, at least one viable alternative explanation, and what would falsify the preferred explanation. Use `docs/principle-synthesis-system.md`.
