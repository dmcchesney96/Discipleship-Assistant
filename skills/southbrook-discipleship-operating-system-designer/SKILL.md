# Southbrook Discipleship Operating System Designer

## Purpose

Turn strong research principles + verified current reality + **practice intelligence + local fit assessment + pilot learning** into an integrated church-wide system that ordinary believers can understand, practice, and reproduce.

## Design rule

A strong system without culture becomes a program. A strong culture without systems becomes inconsistent. Design both.

## Required layers

### 1. Shared definitions
Disciple, maturity, disciple-maker, multiplication, success.

### 2. Discipleship map / environments
What ongoing environments/rhythms every disciple needs access to.

### 3. Pathway / movement
How people move from first contact toward ownership, maturity, mission, disciple-making, and sending. Transformation, not program completion.

### 4. Lifestyle / practices
Abiding, community, obedience, mission rhythms that can live outside programs.

### 5. Disciple-maker development
Invitation, modeling, simple tools, supported practice, coaching, increasing responsibility, reproduction expectation.

### 6. Leadership engine
Identify → Invest → Launch (working language), with apprentices and coaching.

### 7. Ministry integration
Weekend, groups, kids, students, families, young adults, membership, baptism/new believers, volunteer teams, care, evangelism, outreach, missions, church planting.

### 8. Handoffs
Transitions between ministries/stages must transfer relationships, ownership, and next steps—not just records.

### 9. Culture
Leadership modeling, language, stories, expectations, celebration, accountability, preaching/teaching, what gets measured/resourced.

### 10. Measurement + learning
How the system will know whether people are abiding, transforming, belonging, living on mission, discipling others, and multiplying.

## Workflow

1. Start from Southbrook Diagnostic, not a favorite external model.
2. Retrieve strongest applicable synthesis principles, relevant Practice Cards/comparisons, practice-fit assessments, and pilot learning.
3. Preserve what is already healthy; identify what to strengthen, simplify, stop, add, and connect.
4. Map current system and desired system side-by-side.
5. For each proposed component state Practice → Mechanism → Research Backbone → Principle → Local Fit → Local Application.
6. Do not require a named program to have direct causal evidence if its mechanism is credible and Southbrook has useful local pilot evidence; do not integrate/scale solely on external popularity.
7. Test ordinary-person reproducibility and staff-dependency risk.
8. Define interfaces between ministries and leadership layers.
9. Resolve/flag language conflicts rather than silently deciding them.
10. Sequence implementation: immediate, pilot, one-year, multi-year culture.
11. Pair every major system change with measurement and feedback.

## Output

- Operating-system map
- Definitions/shared language
- Pathway + environments + lifestyle
- Disciple-maker and leadership-development loops
- Coaching structure
- Ministry integration matrix
- Handoffs
- Culture levers
- Measurement/learning loop
- Implementation sequence
- Dependencies/risks/unknowns
- Decisions leadership must make

Do not mark design choices approved unless documented.
